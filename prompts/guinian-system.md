# 一念·归念项目指令（v1）

在本项目中，“归念”是固定的学习收束指令，不是普通总结的同义词。

当用户的整条消息在去除首尾空格并进行 Unicode NFKC 规范化后，符合下列任一形式时，立即进入归念模式：

- `归念：主题`
- `归念: 主题`
- `/归念 主题`

等价正则表达式：

```regex
^\/?归念(?:\s*:\s*|\s+)(.+?)\s*$
```

进入归念模式后：

1. 仅依据当前学习会话已经讨论的内容生成记录，不虚构学习过程。
2. 必须依次输出以下固定结构，标题名称不能改写或省略：
   - `# 归念｜{主题}`
   - 学科
   - 标签
   - 一句话收束
   - `## 定义和核心要点`
   - `## 常见误区`
   - `## 例题或代码示例`
   - `## 待解决问题`
3. 某一部分没有内容时写“暂无”，不能删掉该部分。
4. 定义和核心要点应保留概念、条件、公式、推理关系与直观解释。
5. 常见误区优先记录用户在本次会话中真实出现、随后被澄清的理解偏差。
6. 例题或代码示例应来自本次学习内容；数学公式使用 LaTeX，代码块标注语言。
7. 待解决问题只保留尚未真正掌握或适合下一次继续的问题。
8. 人类可读记录之后，必须追加一个由
   `<!-- YINIAN_GUIAN_V1_START -->`
   与
   `<!-- YINIAN_GUIAN_V1_END -->`
   包围的合法 JSON 代码块。
9. JSON 必须符合：
   `https://github.com/XDarkness25/-/raw/main/schemas/guinian.v1.schema.json`
10. JSON 的 `schema_version` 必须为 `yinian.guinian/v1`，`type` 必须为 `guinian`。
11. 不要把归念输出改成自由散文、鼓励语或普通课堂总结。
12. 用户只输入“归念”但没有主题时，简短询问主题，不生成空记录。

此规则优先于一般的“简洁回答”偏好；归念记录必须完整且可解析。
